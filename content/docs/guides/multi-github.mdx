> **Quick Answer: How to use multiple GitHub accounts in parallel**
> To run multiple GitHub accounts simultaneously on the same machine without credential collisions, you must isolate three layers:
> 1. **Commit Identity (`user.name` & `user.email`):** Prevent authorship leaks by setting identity per repository or folder rather than globally.
> 2. **SSH Authentication:** Separate SSH keys using `~/.ssh/config` host aliases or Git `core.sshCommand` with `IdentitiesOnly=yes`.
> 3. **GitHub CLI (`gh`) & HTTPS Tokens:** Keep per-terminal session tokens isolated so concurrent terminal windows or background AI coding agents don't overwrite each other's active session.

Managing multiple GitHub accounts—such as `alice` (personal) and `alice-corp` (work)—on a single machine is one of the most common friction points in modern software development.

Whether you are switching between client work and side projects, or running parallel terminal tabs alongside AI coding agents like Claude Code or Cursor, global credentials inevitably collide.

## The Problem: Why Managing Multiple GitHub Accounts is Frustrating

By default, Git and GitHub assume a single person owns the entire computer. This creates three critical failure modes:

1. **The Global Git Config Leak:** Git defaults to `git config --global user.email`. If you work on an internal corporate repository and then switch to an open-source project, running `git commit` stamps your corporate email into the public Git log permanently.
2. **SSH Agent Key Collisions:** When connecting to `github.com`, the SSH agent offers all loaded keys sequentially until one succeeds. If your personal key has read access to an organization, Git may authenticate as your personal account even when pushing to a company repository.
3. **GitHub CLI (`gh`) Global State Collisions:** The official GitHub CLI (`gh`) stores active authentication globally in `~/.config/gh/hosts.yml`. If Terminal 1 runs `gh auth switch` for work, Terminal 2 (running your personal project in parallel) instantly flips to the work account. This breaks parallel workflows and background AI coding agents.

## Solution 1: Automating Parallel Accounts with GitSwitch

[GitSwitch](https://gitswitch.dev) is built from the ground up to allow multiple GitHub accounts to run in parallel on a single machine with zero manual SSH config hacking.

### Step 1: Install and Enable Shell Integration

```bash
# macOS / Linux (Homebrew)
brew install aksisonline/gitswitch/gitswitch

# Or via install script
curl -fsSL https://gitswitch.dev/install.sh | bash
```

Enable shell integration (which sets up prompt indicators and automatic Session Isolation):

```bash
gitswitch shell
```

Say `yes` to the defaults, then reload your shell (`source ~/.zshrc` or `source ~/.bashrc`).

### Step 2: Connect Your GitHub Accounts

Add your profiles using one-command OAuth device login:

```bash
gitswitch login --profile personal    # Connects alice (personal)
gitswitch login --profile work        # Connects alice-corp (work)
```

Verify your accounts:

```bash
gitswitch list
```

```text
✓  personal        Alice Smith <alice@gmail.com> (gh: alice)
   work            Alice Smith <alice@company.com> (gh: alice-corp)
```

> **Note:** Ensure both accounts are logged in to `gh` (`gh auth login`). GitSwitch uses GitHub CLI tokens to route pushes and API calls automatically.

### Step 3: Claim and Pin Your Repositories

Instead of forcing your repositories into rigid directory trees, simply pin the desired identity once inside each repository:

```bash
cd ~/projects/my-library && gitswitch pin personal
cd ~/work/internal-api   && gitswitch pin work
```

That's the entire setup. Everything from here works automatically:
- Every `git commit` in `~/projects/my-library` is authored as `alice@gmail.com`.
- Every `git commit` in `~/work/internal-api` is authored as `alice@company.com`.
- Your shell prompt visually displays the active profile:
  ```text
  ~/projects/my-library  [personal●] ❯
  ~/work/internal-api    [work●] ❯
  ```

### Step 4: Parallel Terminals and Session Isolation

With GitSwitch's built-in [Session Isolation](/docs/routing/session-isolation), multiple terminals run side-by-side without account interference:

```bash
# Terminal 1 (Work Repo)
cd ~/work/internal-api
gh pr create             # Authenticates and creates PR as alice-corp

# Terminal 2 (Personal Repo, simultaneously)
cd ~/projects/my-library
gh pr create             # Authenticates and creates PR as alice
```

Neither terminal modifies `~/.config/gh/hosts.yml`. GitSwitch dynamically passes the scoped `GH_TOKEN` directly to each command based on directory context.

### Accidental Push Under Wrong Account? Fix It Instantly

If you committed under the wrong email before configuring GitSwitch:

```bash
# Rewrites the last commit author and safely force-pushes
gitswitch reauthor 1 --to personal --push

# Or rewrite multiple commits selectively by old email:
gitswitch reauthor 5 --to personal --from alice@company.com --push
```

## Solution 2: Configuring Multiple GitHub Accounts via Native Git IncludeIf & SSH

If you prefer configuring everything manually without third-party utilities, Git provides native conditional configuration via `includeIf`, combined with SSH host aliases.

### Step 1: Organize Your Repositories into Strict Folders

The native approach requires strict folder discipline. You cannot mix personal and work projects in the same folder:

```bash
mkdir -p ~/git/personal
mkdir -p ~/git/work
```

### Step 2: Generate Dedicated SSH Keys

Generate a unique SSH keypair for each GitHub account:

```bash
# Generate personal key
ssh-keygen -t ed25519 -C "alice@gmail.com" -f ~/.ssh/id_ed25519_personal

# Generate work key
ssh-keygen -t ed25519 -C "alice@company.com" -f ~/.ssh/id_ed25519_work
```

Add the respective public keys (`~/.ssh/id_ed25519_personal.pub` and `~/.ssh/id_ed25519_work.pub`) to your respective GitHub accounts under **Settings → SSH and GPG Keys**.

### Step 3: Configure `~/.ssh/config`

Configure SSH host aliases so SSH routes to the correct key for each account:

```ini
# Personal GitHub Account
Host github.com-personal
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_personal
    IdentitiesOnly yes

# Work GitHub Account
Host github.com-work
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_work
    IdentitiesOnly yes
```

> **Crucial:** `IdentitiesOnly yes` is required to prevent the SSH agent from attempting every available key.

### Step 4: Configure Folder-Specific Git Configs (`includeIf`)

Create separate config files for each profile:

**`~/.gitconfig-personal`**:
```ini
[user]
    name = Alice Smith
    email = alice@gmail.com

[core]
    sshCommand = ssh -i ~/.ssh/id_ed25519_personal -F /dev/null
```

**`~/.gitconfig-work`**:
```ini
[user]
    name = Alice Smith
    email = alice@company.com

[core]
    sshCommand = ssh -i ~/.ssh/id_ed25519_work -F /dev/null
```

Now update your global **`~/.gitconfig`** to conditionally load these configs based on the repository path:

```ini
[includeIf "gitdir:~/git/personal/"]
    path = ~/.gitconfig-personal

[includeIf "gitdir:~/git/work/"]
    path = ~/.gitconfig-work
```

*(Note for Windows: Use forward slashes in path configs, e.g. `gitdir:C:/Users/alice/git/work/`)*.

### Step 5: Cloning Repositories with Native Aliases

When using native SSH host aliases, you **must modify the clone URL** for every repository:

```bash
# Work repository (use github.com-work alias)
git clone git@github.com-work:alice-corp/internal-api.git ~/git/work/internal-api

# Personal repository (use github.com-personal alias)
git clone git@github.com-personal:alice/my-library.git ~/git/personal/my-library
```

If you forget to rewrite the remote host, SSH defaults to standard `github.com` and authentication fails.

## SSH vs HTTPS: The Authentication Divide

A common question when managing multiple GitHub accounts is whether to use SSH or HTTPS:

1. **HTTPS & OS Credential Managers:**
   When cloning via HTTPS (`https://github.com/...`), Git delegates credential storage to helpers such as macOS Keychain, Windows Credential Manager, or Git Credential Manager (GCM). These managers associate credentials with the domain name (`github.com`). Switching accounts often causes the credential helper to overwrite or supply the wrong token, causing `403 Permission Denied` errors or silent account mix-ups.
2. **SSH Authentication:**
   SSH keys bypass the OS credential helper and authenticate directly via public-key cryptography. However, native SSH requires configuring host aliases unless you use a router like GitSwitch.
3. **How GitSwitch Solves Both:**
   GitSwitch routes both SSH and HTTPS automatically. For HTTPS repositories, it supplies the correct scoped OAuth token per repository. For SSH, it assigns the matching key via `core.sshCommand`.

## Operating System Specific Tips

### macOS
macOS stores HTTPS Git credentials in Keychain. If you notice Git pushing with an old account, purge the stored credential:
```bash
git credential-osxkeychain erase
host=github.com
protocol=https
[Press Return twice]
```

### Windows (PowerShell & WSL)
When configuring native `includeIf` in Windows Git:
- Always use forward slashes in `~/.gitconfig` (e.g., `gitdir:C:/Users/username/work/`).
- Trailing slashes are mandatory (e.g., `gitdir:~/work/`, not `gitdir:~/work`).
- Windows Credential Manager caches GitHub tokens under `Generic Credentials` (`git:https://github.com`). Remove stale entries if token collisions occur.

### Linux
Ensure `ssh-agent` is running if using password-protected SSH keys:
```bash
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519_work
```

## Frequently Asked Questions

### Can I use two GitHub accounts on the same computer?
Yes. You can manage multiple GitHub accounts on one computer by assigning separate SSH keys and commit emails to each account. You can isolate them manually using Git's native `includeIf` directive and `~/.ssh/config`, or automatically using [GitSwitch](https://gitswitch.dev).

### How do I use multiple GitHub accounts in parallel without switching?
To run accounts in parallel without switching manually, use directory-based or session-based isolation:
- **Directory Pinning:** Pin your account to the repository or directory so Git automatically selects the correct credentials without modifying global configuration.
- **Session Isolation:** Ensure your GitHub CLI (`gh`) tokens are scoped per terminal session rather than shared globally in `~/.config/gh/hosts.yml`.

### How to change GitHub account in terminal?
To switch your active GitHub identity in the terminal:
- With GitSwitch: Run `gitswitch <profile-name>` (e.g. `gitswitch work`).
- With native Git: Change local repository config using `git config user.email "you@company.com"` and `git config user.name "Your Name"`.
- With GitHub CLI: Run `gh auth switch --user <username>`. (Note: `gh auth switch` changes API tokens globally, not commit emails).

### Why does Git push to GitHub using the wrong account?
Commit authorship and push authorization are handled by completely different mechanisms:
- **Author identity** is controlled by `user.email` in Git config.
- **Push credentials** are determined by your SSH key or HTTPS credential manager.
If your `user.email` is set to your work address but your SSH key or macOS Keychain supplies your personal token, GitHub accepts the push from your personal account while displaying the work author email, causing avatar and permissions mismatches.

### Can I have a personal and work GitHub account on the same machine?
Yes. Having both personal and work accounts is supported by GitHub's Terms of Service. Using per-repository pins or `includeIf` configurations guarantees that work proprietary code is never committed under your personal handle or pushed using personal keys.
